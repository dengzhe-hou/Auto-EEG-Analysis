# AEA per-skill acceptance

The approved engineering evaluation covers one frozen AEA version. Each of the 22 skills has three named bounded tasks, each repeated in three independent Haiku 5.5 CodeAct sessions with disabled thinking and medium effort. The total is 198 first deliveries. The assigned skill entrypoint is included in the initial message and its linked procedures and helpers are locally available. Input fixtures are small synthetic signals, fixed stage records or intentionally mismatched records. The prompt states the requested calculations, units and decisions. References and grading code stay outside the model workspace. No real participant recordings are used.

The endpoint is a binary check of the specified result values, fields and, where requested, an actual readable or traceable artifact, with a retained analysis program and execution trace. A missing delivery or mismatched field is a failed acceptance. Shared infrastructure incidents are recorded separately and suspend admission. Each skill has its own nine-delivery denominator. The base suite measures the named operations or workflow checks. In particular, audit covers the assigned review decision, recipe covers applicability, and the source inverse and ICA use supplied fixed operators. No broader scientific or model-effect claim is made from those bounded checks.

SkillsBench uses fixed tasks, executable verifiers and repeated agent trials (https://arxiv.org/abs/2602.12670). Its tasks and comparison arms address a different question. This suite uses the same reproducible checking principle for specified EEG skill operation acceptance. Previous AEA paired trials and ERP cross-toolbox comparisons retain their own endpoints and results.

Reuse the existing CPU Apptainer image and metered client. Implementation assumption is the last fetched public main commit saved in BASE_COMMIT.txt. The approved incremental cap is USD 5, inclusive of successful calls and known or unresolved charges. No model grading. Use one Slurm worker with 1 CPU and 4 GiB and no GPU, matching the latest comparable serial run. Based on prior per-session means of about 18–37 seconds and 90 seconds for the slower group ERP examples, the 33-session batches have a 75-minute limit using the slower duration times the 1.5 planning factor. Queue time is separate. The one-route configuration avoids relying on a worker IP mapping that was not available in the previous run.

Order is deterministic fixture and verifier preflight, per-skill session batches, aggregate checks and reporting. Completed first deliveries and errors are retained. No manuscript synchronization or public release is part of this task.
